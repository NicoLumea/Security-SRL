# Dominion / Concept 04 — Implementation report

## Original concept identity

The existing concept gallery names the fourth direction **Dominion / Confident Presence**.
The established moodboard uses a near-black charcoal background (`#151715`), a muted brass tone (`#a58b5d`), an oversized tilted elliptical ring, asymmetric placement and large display type with a lighter italic contrast. The gallery phrase is “A STRONGER PRESENCE.” No new brand name or media has been invented.

## Implementation

- Independent responsive Astro page at `/concepts/dominion/ro/` and `/concepts/dominion/en/`.
- Hero, navigation, services, approach, demonstrative process, portfolio, contact form and footer.
- Strong asymmetry, monumental typography, ring geometry and a dedicated design stylesheet without modifying Sentinel, Vanguard or Precision visual code.
- Shared gallery and switcher automatically expose Dominion once the `available` flag becomes `true`.
- Reuses approved `facade.jpg` and `surveillance.jpg` and existing bilingual editorial service/project material.
- All portfolio entries remain visibly marked as **demonstration examples**, not company installations.
- Company history, staff, achievements, certification, contact details and actual operating process are **not invented**.

## Accessibility, performance and motion

Semantic headings and links, visible keyboard focus, native `details` navigation, responsive images generated by Astro, lazy loading below the fold, no extra third-party packages. Optional intersection animations use the Web Animations API, do not hide the default content and respect `prefers-reduced-motion`. Code is in a compiled external module compatible with the project's CSP. There is no new video.

## Localization

Romanian and English are built using the established static route architecture with language switching and metadata via `Base.astro`.

## Contact form limitation

The form validates in-browser and explicitly states that no message is sent or stored. It intentionally does not call an unapproved endpoint. Real details, recipient and backend must be approved before any production launch.

## Testing

- New browser tests cover viewport widths 320, 390, 768, 1024, 1440 px; gallery switching; localization; mobile menu; form non-transmission; reduced motion; accessibility; screenshots.
- Worker test matrix now checks both Dominion URLs.
- Existing gallery assertions now expect all four concepts to be available.
- All project checks are expected to run in GitHub Actions; inspect the latest CI result before approval.
- Real-device iOS Safari is **not** verified by Chromium tests.
